### ドキュメントはもうHTMLが基本でいい──高校生のタロット占いと、AI時代の「見せる力」

資料を作るとき、まず何を開くだろうか。Word、PowerPoint、あるいはエンジニアならMarkdown（見出しや箇条書きを記号で書く軽量な書式）かもしれない。

私は最近、この順番が変わりつつあると感じている。結論から書くと、**AIを使う前提に立つなら、ドキュメントはもうHTMLが基本でいい**と思っている。そう考えるようになったきっかけは、ある高校生との出会いだった。

#### 高校生が作っていたタロット占い

先日、とあるAIコミュニティで、びっくりするくらいクオリティの高いアウトプットを作る高校生に出会った。

見せてくれたのは、あくまでサンプルとして作ったタロット占いのWebページだ。HTML（Webページの骨組み）、CSS（見た目の指定）、JavaScript（動きの指定）だけでできた静的なHTMLファイルで、ビジュアルも本格的だった。

<!-- 実体験：見たときの率直な驚き、高校生が楽しそうに説明していた様子 -->

作り方を聞くと、「チャッピー」（ChatGPTの愛称）に指示を出したり、参考になるネタを渡したりして、会話していただけだという。プログラミングを学んだわけでも、npm（JavaScriptの部品を管理する仕組み）やフレームワークを知っているわけでもない。

それを見たときにも思ったし、最近サイトを作るのが趣味になってから、なおさら強く感じていることがある。ドキュメントはもうHTMLを基本に考えていいのではないか。

#### 1つのファイルに、ここまで入っている

サンプルとはいえ、そのタロット占いのファイルを手元で開いてみると、改めて驚かされる。ファイルは1つだけで、トップに飾られた画像も文字のデータに変換してファイルの中に埋め込まれている（データURIという方法）。

中身を整理すると、次のようになる。

| 中身           | 実際の内容                                                     | HTMLだからできること                           |
| -------------- | -------------------------------------------------------------- | ---------------------------------------------- |
| 占いの流れ     | テーマや質問を選び、カードを1枚引いて結果を表示する            | 画面の切り替えをJavaScriptだけで実現できる     |
| データ         | カードごとの意味や、テーマと質問の一覧                         | データと画面を同じファイルに持てる             |
| 結果           | 選んだ質問と引いたカードの組み合わせで、結果の文章を出し分ける | 組み合わせに応じて内容を組み立てられる         |
| 見た目         | 星のまたたきや、カードがめくれる動きなどのアニメーション       | CSSだけで動きを付けられる                      |
| 画面の大きさ   | 画面の幅に応じてレイアウトを切り替える                         | スマホでもパソコンでも、同じファイルで見られる |
| 見る人への配慮 | OSで「動きを減らす」設定をしている人にはアニメーションを止める | ブラウザの仕組みに乗って、見る人に合わせられる |

カードは毎回ランダムに引かれる。画像を読み込めないときに備えて、代わりの表示まで用意されている。

**占いの流れも、質問も、カードの意味も、動きも、すべてが1つのHTMLファイルに収まっている**。サーバーもデータベースもいらない。メールで送っても、USBメモリで渡しても、ダブルクリックすればブラウザで開ける。

PowerPointでも、スライド同士をリンクでつなげば、選んだ答えに応じて画面を進める程度の分岐は作れる。ただ、たくさんの質問から選ばせ、カードをランダムに引き、組み合わせごとに結果の文章を組み立てるとなると、マクロ（PowerPointに組み込むプログラム）なしでは難しい。Markdownはもともと動きを付けるための形式ではない。

#### HTMLを基本にしたい理由

タロット占いを入り口に、私がHTMLを基本にしたいと考える理由を整理しておく。

##### ① 表現の幅が広い

Markdownは書きやすく、記号のまま読んでも意味が通る。その代わり、見た目の表現は文字と表、リンクが中心になる。PowerPointは見た目を自由に作り込めるし、アニメーションやスライド間のリンクも使えるが、基本はスライド1枚ずつの単位で考えることになる。

HTMLなら、文章も表もグラフも、クリックで切り替わる画面も、1つのページに自由に並べられる。関係するデータをJSON（データを書くための形式）でまとめて同じファイルに持たせれば、データと見せ方を一体にできる。冒頭のタロット占いもカードの意味と質問をデータとして持ち、選ばれた組み合わせに応じて結果を組み立てている。

| 観点               | Markdown                         | PowerPoint                                 | HTML                               |
| ------------------ | -------------------------------- | ------------------------------------------ | ---------------------------------- |
| 人が手で書く       | 書きやすい                       | 直感的に作れる                             | 手では大変（AIに任せる）           |
| 表現の幅           | 文字・表・リンクが中心           | スライド単位で自由にレイアウトできる       | ページ全体を自由にレイアウトできる |
| データとの一体化   | 難しい                           | グラフやExcelの表を埋め込める              | JSONと一緒に持ち、表示を切り替える |
| 操作できる要素     | ほぼなし                         | アニメーション、リンクでのスライド移動など | 切り替え・絞り込み・計算など       |
| 見る側に必要なもの | そのままでも読める（整形は別途） | PowerPointや互換アプリ                     | ブラウザ                           |
| 職場での受け渡し   | エンジニアの間が中心             | 多くの職場で標準                           | まだ一般的ではない                 |

私自身の実感としても、この表現の幅は効いている。外にある複数の情報を一つにまとめてグラフにして見せるだけで、めちゃくちゃ分かりやすくて便利だと喜ばれたりする。私は何も手を動かしていない。Claude Codeに頼んだだけだ。

ここで効いているのは、私のプログラミングの腕ではない。「この情報とこの情報を並べてグラフにしたら、分かりやすいのではないか」という発想のほうだ。HTMLはその発想をそのまま形にできる器になっている。

##### ② 画像も音も、文字にして1つのファイルに収められる

HTMLでは画像や音声、動画、フォントといったファイルを、文字の並びに変換してページの中に直接書き込める。データURIと呼ばれる仕組みで、`data:image/webp;base64,…` のように、画像の中身そのものをアドレスの代わりに書く。冒頭のタロット占いが、トップの画像を1つのファイルに収めていたのも、この方法だ。

こうすると、画像を表示するのも、音声や動画を再生するのも、そのファイル1つで済む。別の画像ファイルを一緒に送ったり、置き場所のパスを合わせたりする必要がない。「1ファイルを渡せば、相手の画面で同じように見られる」という手軽さは、この仕組みに支えられている。

PowerPointも画像や動画をファイルの中に持てるが、.pptxの中身は複数のファイルをまとめたzip形式で、専用のアプリで開く前提になる。HTMLは、画像まで含めて全体が1つのテキストだ。メールに添付しても、チャットで送っても、文字のファイルとしてそのまま扱える。Markdownでは、画像は別のファイルとして置くのが一般的だ。

ただし、MDN（Webの技術資料サイト）が「小さなファイル」を埋め込むための仕組みと説明しているとおり、大きなファイルには向かない。Base64という方式で文字に変換すると、データの大きさは元の約1.33倍になる。数MB（メガバイト）を超える動画などは、別のファイルとして置いたほうがよい。

##### ③ ブラウザさえあれば見られる

PowerPointも多くのパソコンに入っていて、PDFに書き出せば誰でも見られる。ただ、PDFにすると操作できる要素は失われるし、スマホの小さな画面ではスライドが見づらいことも多い。

HTMLなら、パソコンでもスマホでも、ブラウザで開くだけでいい。画面の幅に合わせてレイアウトを変えることもできる。インターネットとブラウザを誰もが使う今、これほど多くの人が特別な準備なしに開ける形式は、ほかにちょっと思いつかない。

##### ④ 置くだけで公開できる

公開してよい情報なら、もはやWebに置いて、ブラウザで見てもらえばいい。たとえばCloudflare Pages（Cloudflareの静的サイト公開サービス）を使えば手軽だ。

Cloudflare Pagesには「Direct Upload」という方法があり、GitHubと連携しなくても、管理画面にフォルダかzipファイルをドラッグ＆ドロップするだけで公開できる。公開先には `<プロジェクト名>.pages.dev` というアドレスが用意されるので、独自ドメインを取得しなくても公開できる。

| 項目                     | Cloudflare Pages（無料プラン）              |
| ------------------------ | ------------------------------------------- |
| 公開方法                 | ドラッグ＆ドロップ（フォルダかzip）         |
| GitHub連携               | 不要（あとからGit連携には切り替えられない） |
| アドレス                 | `<プロジェクト名>.pages.dev`                |
| ドラッグ＆ドロップの上限 | 1,000ファイル、1ファイル25MiBまで           |
| 静的ファイルの配信       | 無料                                        |

ひとつ補足しておくと、Cloudflareは今、新しく作るプロジェクトにはPagesではなくWorkers（同社のプログラム実行サービス）の静的アセット機能を使うよう案内している。Pagesは引き続き使えるが、新機能はWorkers側に集中させる方針だ。とはいえ、HTMLファイルを置いて見てもらうだけなら、ドラッグ＆ドロップで済むPagesがいちばん手軽だと私は思う。

なお、pages.devのアドレスは、アクセス制限を設定しない限り、インターネット上の誰でも開ける。社外秘や個人情報を含む資料は置かないこと。ここだけは押さえておきたい。

##### ⑤ 「どう見られるか」のルールまで決まっている

私は、HTMLこそ、インターネットとブラウザを前提にした時代に、最も適したドキュメント形式ではないかと思っている。そう考えるいちばんの理由は、HTMLが**中身だけでなく、どう見られるかまで決められる仕組みの上にある**ことだ。

分かりやすいのがOGP（Open Graph protocol）だ。SNSやチャットにURLを貼ると、タイトルや画像の付いたカードが表示される。あの見え方はページのHTMLに書かれた `og:title`（タイトル）や `og:image`（画像）などの情報から作られている。もともとFacebookで生まれた仕組みで、すべてのページに必須の項目として `og:title`、`og:type`、`og:image`、`og:url` の4つが定められている。このブログの記事末尾にある情報ソースのカードも、相手のページのOGPを読み取って表示している。

OGPのほかにも、HTMLを中心としたWebには、見られ方や読まれ方を支える共通の仕組みがいくつも用意されている。

| ルール                       | 決めていること                                               | 効いてくる場面                     |
| ---------------------------- | ------------------------------------------------------------ | ---------------------------------- |
| OGP                          | リンクを貼ったときのタイトル・説明・画像                     | SNSやチャットで共有するとき        |
| viewport                     | 画面の幅に合わせた表示の大きさ                               | スマホで開くとき                   |
| 構造化データ（JSON-LD）      | ページの内容（記事、イベントなど）を決まった形式で伝える     | 検索エンジンがページを理解するとき |
| アクセシビリティ（WCAG）     | 障害のある人にも内容が伝わるようにする指針。画像の説明文など | 画面の読み上げソフトで読むとき     |
| robots.txt・robotsのmetaタグ | 検索エンジンなどのクローラーに、読んでよい範囲を伝える       | クローラーが訪れるとき             |

robots.txtについては以前の記事で詳しく書いた。

[[ogp:https://tariki-code.tokyo/blog/2026-10-31-robots-txt-ai-training-signal-search-vs-training]]

そして、こうしたルールが長く使えることも大きい。HTMLの仕様をまとめるWHATWGは、後方互換性（古いものを壊さないこと）を基本原則のひとつに掲げてきた。仕様は「Living Standard」として更新され続けるが、互換性を崩す変更は極めて慎重に扱われ、一度入った機能を取り除くことも難しいとしている。昔作ったHTMLの多くが今のブラウザでもそのまま開けるのは、このためだ。

PowerPointやMarkdownのファイルを共有するとき、リンクを貼ったときの見え方は、保存先のサービスや開くアプリに任せることになる。HTMLなら、その見え方まで作る側が決められる。作る、見せる、共有する、探してもらう、のそれぞれに共通の仕組みがあり、ブラウザや検索エンジン、SNSなどがそれに沿って動いている。私が「最も適した」形式だと考えるのは、この点だ。

#### AI時代に変わったのは「作る側」

ここまで挙げたHTMLの長所は、実は昔からあったものだ。それでもHTMLが日常のドキュメントにならなかったのは、作るのが難しかったからだと思う。

これまで「Webページを作る」と言えば、エンジニアの仕事だった。HTMLやCSSの書き方を覚え、開発の道具をそろえ、フレームワークを学ぶ必要があった。

今は違う。ファイルを1つ作るくらいなら、GeminiやChatGPTに必要な情報を聞きながら、誰でもできる。冒頭のタロット占いも、コードを書いたのはAIだった。

MarkdownやYAML（設定ファイルなどに使われるデータの書式）も、AIやシステムが扱いやすい面はある。ただ、どちらも人が読み書きする前提でつくられた形式だ。手で書きやすいように記号を減らし、表現をあえて絞っている。AIに書かせることを前提にすると、その「書きやすさ」の利点は薄れる。書く手間をAIが引き受けてくれるなら、表現に制限の少ないHTMLのほうが有利になる。

もう少し凝りたければ、裏側のAPI（ほかのサービスとデータをやり取りする窓口）やデータベースと連携させればいい。このブログのいいねボタンやお問い合わせフォームも、その一例だ。ただ、そこまでしなくても、HTMLは十分に役に立つ。

私たちはHTMLを「システムの画面を作るための技術」だと考えがちだ。でも、もうそれだけではない。**HTMLは誰でも作れて、誰でも見られる、表現の幅の広いドキュメントの形式**になっている。ここまで制作のハードルが下がると、重要になるのは技術だけでなく「何を使って、何を表現するか」というアイデアだ。

#### 業界でも広がる「見せる」表現

これは私だけの感覚ではないらしい。2026年5月、AnthropicのClaude Codeチームのエンジニア、Thariq Shihipar氏が「HTML is the new Markdown（HTMLは新しいMarkdownだ）」と発信した。

同月のLenny's Newsletterのインタビューで、同氏は数千行に膨らんだMarkdownの計画書を読まなくなっていたことに気づき、計画書や仕様をClaude CodeにHTMLで作らせるようになったと話している。理由として挙げているのは、操作できる要素や画面のモックアップ、スクロールできるセクションなど、HTMLのほうが表現が豊かで、情報の密度も上げられることだ。上司への週次の状況報告もHTMLで送っていて、MarkdownやプレーンテキストよりHTMLのほうが「実際に読まれやすい」という。

AIのサービス側も文章だけを返す形から、見せる形を作り、そのまま公開する方向へ広がっている。

| サービス                  | 作れるもの・できること（公式の説明）                                        | 対象                                        |
| ------------------------- | --------------------------------------------------------------------------- | ------------------------------------------- |
| Claude Artifacts          | 文書、1ページのWebサイト、図、ダッシュボード、小さな対話型ツール            | 無料プランを含む全プラン                    |
| Gemini Canvas             | アイデアを共有できるアプリやゲームにするコード、Webページなど               | すべてのGeminiユーザー                      |
| Gemini Notebook           | ノートに集めた資料から、操作できるサイトを作る（2026年11月16日発表）        | 18歳以上のユーザー（Webで順次）             |
| ChatGPT（Intelligent UI） | 回答の中に比較表や図、計算機などの操作できる要素を組み込む                  | 2026年10月7日から順次（Free・Goは翌日から） |
| ChatGPT Space             | 操作できるページやプレゼンテーションを作り、共同で編集する                  | 2026年11月20日からPlusへ順次（18歳以上）    |
| ChatGPT Sites             | Webサイトや軽いアプリを作り、ホスティング（置き場所の用意）から公開まで行う | Plus・Proなどの有料プラン（Free・Goは不可） |

Gemini Notebookではチャットに「make me a site」と入力し、作りたいサイトの内容を説明すると、ノートに集めた資料をもとにサイトを作ってくれる。公式ブログでは作れるサイトの例として、試験勉強用の周期表や年表、四半期の売上を見るダッシュボード、プロジェクトの進捗管理表などを挙げている。公式の発表では触れられていないが、私が試した限りでは、サービスの中で見られるだけでなくHTMLファイルとしてダウンロードもできた。GPT-6のシステムカードを資料にして作ったサイトは、約80KBのHTMLファイル1つで、グラフ（Chart.js）やアイコン、フォントはネット上の配信元から読み込む作りだった。手元に残したり、Cloudflare Pagesなど別の場所に置いたりもしやすい。

ChatGPT Spaceは、2026年11月20日に配信が始まったばかりの機能だ。中身がHTMLかどうかまでは公式に書かれていないが、「文章ではなくページとして見せる」という方向ははっきりしている。ただし、共有された相手もSpaceを使える有料アカウントが必要で、公開リンクは使えない。ChatGPT Sitesも公開範囲は広げられるが、使えるのは有料プランだけだ。誰でもブラウザで開けて、無料でどこにでも置けるという点では、HTMLファイルとして手元に持てることの強みは大きい。

#### HTMLにも向き不向きがある

とはいえ、HTMLが何にでも向いているわけではない。

Cloudflareは2026年2月、AIエージェントがWebページを読みにきたとき、HTMLをMarkdownに変換して返す「Markdown for Agents」という機能を始めた。同社の例では、あるブログ記事がHTMLだと1万6,180トークン、Markdownにすると3,150トークンで、AIが読む量を約80%減らせたという。AIが情報を「読む」ときには、飾りのないMarkdownのほうが効率がよい。

PowerPointにも、まだ強い場面がある。組織のテンプレートに沿って提出する資料や、受け取った相手がそのまま手を入れて使い回す資料は、PowerPointのほうが話が早い。整理すると、私はこう考えている。

| 場面                                         | 向いている形式     |
| -------------------------------------------- | ------------------ |
| AIに資料を読ませる（入力）                   | Markdownやテキスト |
| 相手がそのまま編集して使い回す、提出用の資料 | PowerPointなど     |
| AIに作らせて、人に届ける（出力）             | HTML               |
| データを保存・受け渡しする                   | JSONなど           |

ドキュメントの本来の目的は人に伝えることだ。そう考えると、**人に届けるドキュメントの基本はHTMLでいい**という結論は変わらない。

HTMLそのものの弱点も書いておく。

- 変更の差分が読みにくい：HTMLはタグが多く、どこを直したかを追うのはMarkdownより大変
- 作るのに時間とトークンがかかる：同じ内容でも、Markdownより出力が長くなる
- 中身の正しさは別問題：見た目が立派でも、グラフの元データが間違っていれば意味がない
- 公開範囲の管理：アクセス制限を設定しない限り誰でも見られるうえ、一度見られたものの保存やコピーまでは取り消せない

特に3つ目は大事だと思う。見た目が整うほど、内容まで正しく見えてしまう。**AIに作らせたHTMLほど、元の数字や出典を自分の目で確かめたい**。

#### ビッグテックには、HTMLで働く文化を引っ張ってほしい

HTMLが日常のドキュメントの基本になるかどうかは、個人の工夫だけでは決まらない。毎日使うAIツールがどの形式を作りやすくしているかで、働き方そのものが方向づけられていくからだ。最後に、この記事でいちばん言いたいことを書いておきたい。

Gemini NotebookのHTMLダウンロードやChatGPT Sitesのように、作ったものをHTMLとして持ち運べたり、そのまま公開できたりする機能が増えているのは、追い風だと思う。こうした機能が充実していくことが、HTMLで仕事をする流れの後押しになってほしい。

一方で、気になる動きもある。AnthropicはClaudeの機能を広げる「スキル」をGitHubで公開していて、その中にはPowerPointやWord、Excel、PDFを作るためのスキルも含まれている。Claude自体も2025年9月からPowerPointのスライドを作れるようになり、2026年9月にはCowork（作業を任せられる機能）とチャットが一つになって、頼めばスライドを下書きし、PowerPointの形式で書き出せるようになった（有料プランでベータ提供）。

前の節で書いたとおり、PowerPointが必要な場面は今もある。利用者のニーズに応えるという意味では、AIでPowerPointを作りやすくするのも自然な流れだと思う。

ただ、私がビッグテックに期待したいのは、従来の形式をAIで作りやすくすることだけではない。

私自身、PowerPointでは文字の位置をそろえたり、図形を並べ直したり、最後は手作業で調整したりすることが少なくなかった。AIでその手間が減るのはありがたいが、そもそもPowerPointという形式で作る必要があるのか、という問いもあってよいはずだ。

HTMLなら、AIに作ってもらったものを、そのままブラウザで見せられる。必要に応じて修正したり、データを更新したりすることもできる。もちろん用途によるが、これまで手作業で整えていた資料の多くは、こうした形に置き換えられるのではないか。

| 段階         | 資料の作り方                                                       | 残る手間                                                           |
| ------------ | ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| 従来         | 形式（PowerPointなど）が先に決まり、人が文字や図形を配置して整える | 作成もレイアウトの調整も、ほぼすべて手作業                         |
| 今のAI活用   | 従来の形式のまま、AIで効率よく作る                                 | 作成の負担は減るが、形式に合わせた調整は残りやすい                 |
| 目指したい姿 | 伝えたい内容に合わせて、AIがHTMLを作る                             | ブラウザで見せ、操作し、共有する。手でレイアウトを整える作業が減る |

だからこそ、ビッグテックにはPowerPointなど既存の形式への対応だけでなくHTMLを使った資料作成や共有の仕組みも、もっと充実させてほしい。

PowerPointを使わないように仕向けるのではなく、HTMLのほうが便利だから自然と選ばれる。そんな環境が整えば、資料づくりにかけていた手作業も、少しずつ減らしていけると思う。

**従来の仕事をAIで効率化するだけでなくAIを前提に仕事のやり方そのものを変えていく**。私が期待しているのは、そういう変化だ。

#### まとめ

- ChatGPTとの会話だけで、本格的なタロット占いのHTMLを1ファイルで作れる時代になった
- HTMLは表現の幅が広く、画像まで1ファイルに収められ、ブラウザだけで見られ、置くだけで公開できる
- AIで作る側の負担が下がり、各社のサービスも「見せる形」を作る方向に進んでいる。AIに読ませるならMarkdown、人に届けるならHTML
- 従来の形式をAIで効率化するだけでなく、HTMLが自然と選ばれる環境を、ビッグテックには整えてほしい

HTMLはもうエンジニアだけの道具ではない。AIがコードを書いてくれる今、私たちは文字や図形をどう配置するかよりも、何を、どう伝えたいかに時間を使えるようになった。
冒頭のタロット占いのように、技術的な作業はAIに任せ、人はアイデアや中身に集中する。そんなドキュメントの作り方がもっと当たり前の世の中にシフトしていくことを願う。
